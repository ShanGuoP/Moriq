# 资源库源码目录

`lib.rs` 保留公共类型、共享辅助函数和模块入口；具体功能按职责分目录。

| 目录 | 职责与主要入口 |
| --- | --- |
| `library/` | 资源库创建、打开和升级入口（`core.rs`），以及封面、设置、移除和引用文件重连 |
| `catalog/` | 素材查询与分页（`query.rs`）、字段编辑（`edits.rs`）、批量修改、项目、文件夹、地点和项目隔离 |
| `media/` | 缩略图和预览访问（`access.rs`）、解码、原图分块、视频、RAW、SVG、色彩及媒体元数据 |
| `ai/` | AI 结果、分类配置、分析结果提交、人像和相似性数据 |
| `transfer/` | 文件发现、导入准备与提交（`commit.rs`）、导出及 Synco 互通 |
| `tasks/` | 后台任务与取消控制 |
| `maintenance/` | 备份、检查修复、孤立文件、回收站清理及空间统计 |
| `database/` | 数据库读取连接、操作日志、初始表结构和 SQL 迁移脚本 |
| `tests/` | 原入口文件的回归测试（`library.rs`），以及独立的 AI、存储和项目隔离测试模块 |

各功能文件内原有的单元测试继续保留在对应实现旁边。

## 接口与模块关系

目录负责归类源码。`lib.rs` 使用 `#[path = "..."]` 显式声明模块，保留
`moriq_library::media`、`moriq_library::jobs` 等已有接口路径和模块可见性。
这样移动文件不会改变应用层的调用路径，也不会扩大内部模块的访问权限。
新增功能文件时，应在对应目录中创建，并在 `lib.rs` 的对应分组中声明。

## 数据库迁移

- `database/schema.sql` 创建版本 1 的初始结构。
- `database/migrations/migration_N.sql` 按数据库结构版本保存升级步骤。
- `library/core.rs` 根据数据库的 `user_version` 执行尚未应用的迁移；已有资源库升级前保留数据库备份。
- 版本 12 直接更新版本号；版本 25 的项目隔离在 `catalog/project_isolation.rs` 中配合文件操作完成。
- 版本 26 由 `catalog/workspace.rs` 执行 SQL 并迁移项目所属数据。

迁移编号表示数据库结构版本，与产品版本号无关。历史迁移用于兼容旧资源库，
应保留原文件和执行顺序。移动 SQL 后，要同步更新调用文件中的 `include_str!` 相对路径。

## 开发验证工具

独立运行的测速、媒体探测和验收数据生成工具仍位于 crate 的 `examples/` 目录；
它们不属于 `src/` 的运行入口。
